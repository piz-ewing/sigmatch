# 扫描优化复验与性能对比

日期：2026-11-19。对象：sigmatch 0.3.4 本次待提交改动。

复验未发现阻止提交的问题。合并版在本机 `.text` 全扫描上，相比原始除法版耗时下降 **40.8%**，相比仅移位版再下降 **20.3%**。整模块扫描分别下降 **40.9%** 和 **20.6%**。两种架构的 Debug/Release 测试以及严格 Clippy 均通过。

## 测量方法

先编译三个版本并保存各自的 benchmark 可执行文件，再串行执行五轮。各轮顺序分别为：

1. 原始除法、仅移位、合并版。
2. 合并版、仅移位、原始除法。
3. 仅移位、原始除法、合并版。
4. 合并版、原始除法、仅移位。
5. 原始除法、合并版、仅移位。

计时期间没有并行执行编译或测试。未固定 CPU 核心或频率；结果是该机器热缓存、该模式下的端到端墙钟时间，不包含统计置信区间。

- 对象固定为 `ntdll.dll`：`.text` 为 **1,507,328 bytes / 1.4375 MiB**，整模块为 **2,539,520 bytes / 2.421875 MiB**。
- 模式为 `DE AD BE EF 13 37 C0 DE DE AD BE EF 13 37 C0 DE`；所有扫描均为 **0 命中**。
- 每个进程先预热 `.text` 20 次、整模块 10 次；各场景计时 200 次，取中位数。主表再取五个进程中位数的中位数。
- 全扫描的计时包含模式解析、查询准备、扫描和销毁；模块绑定、节表取得和页属性 census 在计时外。
- 单字节场景预先解析 `90` 模式，在 `.text + 16` 开始、长度为 1 的窗口重复 20,000 次。计时包含查询构造、页查询、分配、匹配、销毁和计时器开销，不能单独代表 VirtualQuery 的耗时。
- 吞吐量 = 扫描字节数 / 中位耗时 / 1,048,576。

当前版本复跑命令：

```powershell
cargo bench --locked --offline --bench scan
```

三版本比较时，对每个独立目录使用相同清单、锁文件、benchmark 和依赖，按上述说明准备 `lib.rs`，用以下命令预编译，再按轮次顺序直接运行各自输出的可执行文件：

```powershell
cargo build --locked --offline --release --bench scan --message-format=json
```

## 收益来源和阻塞页验证

每个 benchmark 进程都对整个镜像地址区间执行 VirtualQuery census，使用与扫描器相同的可读保护判断：

| 镜像 | 可读字节 | 阻塞字节 |
| --- | ---: | ---: |
| ntdll.dll | 2,539,520 | 0 |
| benchmark 主模块 | 237,568 | 0 |

因此这里的主基准收益不依赖跳过阻塞页。代码路径上，合并版将大部分逐候选的 `range_readable` 替换为候选所属 run 的 span 上限比较；不能仅凭这些时间拆分每条指令、每次分配或 VirtualQuery 的单独成本。

另行运行预计算 run 的迭代计时用例：

```powershell
cargo test --locked --offline --release --lib blocked_pages_reduce_candidate_iteration_work -- --ignored --nocapture
```

本次一次输出为：全可读 `2,097,137` 个候选 / `1.1155 ms`；一半阻塞 `1,048,561` 个候选 / `398.8 µs`。它只计候选迭代，排除了 run 预计算、VirtualQuery 和模式比对，也没有多轮统计；该结果只作补充记录，不用于推导主基准收益或宣称跳页零成本。真实 PAGE_NOACCESS 页上的正确性由下述独立断言测试验证。

## 正确性、稳定性与代码质量

本轮新增了超过一页的模式测试，覆盖候选窗口止于前一页、模式仍须读入后续可读页的兜底路径，以及跨越真实 PAGE_NOACCESS 页时的拒绝；两个方向都与独立页布局结果比较。原有随机差分测试覆盖 32 轮真实分配、随机阻塞布局、模式、通配符和窗口，并验证前后向结果、顺序和无重复。真实主模块 `.text` 差分测试必须成功绑定并取得节，不能静默跳过。

本次改动的关键约束已复核：

- `next_address` 返回地址及其原属 run；内部切换 run 后，旧候选仍使用旧 limit，防止跨进阻塞页。
- 相邻可读页合并；候选上下界与可读 span 上限各自保留；超出缓存 run 范围时仍使用完整页检查。
- `Pattern::compare` 明确为私有 unsafe 方法并写出调用契约；普通匹配保留检查入口，引用读取仍各自执行 `range_readable`。
- 页索引仍检查减法下溢和数组范围；page_shift 从已校验的二次幂页大小计算；span 加法保留溢出检查。
- benchmark 与库共享私有页保护判断；没有新增公共 API 或依赖。
- 真实页测试使用 RAII 释放分配，保护页状态也限制测试写入；x86 合成地址不超出 usize。

## 适用边界

这次复验覆盖稳定内存映射下的边界、保护判断、溢出和迭代行为，不构成并发内存修改的安全保证。页属性缓存是查询准备时的快照；扫描期间如果另一个线程改变保护、解除映射或并发写入目标内存，已有缓存无法同步这些变化。这是原实现已有的前提，本次优化未引入同步机制。

主性能基准只覆盖本机 ntdll、16 字节无命中模式和热缓存。高命中率、长模式、通配符密集、碎片化保护和高频小查询的收益可能不同。阻塞页跳过的有效性有正确性测试，但本报告不提供包含准备阶段的阻塞页端到端性能结论。
